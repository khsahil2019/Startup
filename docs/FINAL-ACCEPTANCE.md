# Startup Impact — Final Acceptance Checklist

This is the final project acceptance checklist. The project is not described as an MVP.

## Founder
- [ ] 75-question questionnaire is available.
- [ ] Majority of questions use structured dropdown/select controls.
- [ ] Autosave works.
- [ ] Founder can leave and resume.
- [ ] Required questions are validated before submission.
- [ ] Evidence can be uploaded.
- [ ] Founder can see a change-request message.
- [ ] A change-request response creates a new submission version.

## Administration
- [ ] Super Admin manages all Universities.
- [ ] University Admin is tenant-scoped.
- [ ] Startup creation and founder invite work.
- [ ] Submission queue works.
- [ ] Admin can inspect answers and derived metrics.
- [ ] Admin can request changes.
- [ ] Admin can verify and publish.
- [ ] Evidence can be verified/rejected.
- [ ] Audit trail is retained.

## Public
- [ ] Only verified/published startups appear publicly.
- [ ] University page matches the master UI reference.
- [ ] Startup directory search/filter works.
- [ ] Startup profile contains the agreed ten information panels/tabs.
- [ ] Valuation, Investability, AI Resilience, SDG and Uniqueness are derived outputs.
- [ ] Road Ahead and Business Plan are displayed.
- [ ] Clients & Revenue is displayed when data exists.
- [ ] Back to University uses the configured University URL.

## Integration
- [ ] University webmaster receives only the integration URL/instructions.
- [ ] Core source code and methodology remain on the Startup Impact server.
- [ ] Updating Startup Impact does not require modifying the University website menu link.
